STUDY PIPELINE STAGE S01 • SOURCE EXTRACTION AND INITIAL HTML

Read /prompts/00-shared.txt rules (or use the Study Project's identical persistent rules). Determine subject and lecture slugs from supplied PPT/transcript or established current-conversation state. If ambiguous in a way that risks writing to the wrong course, request clarification, WAIT_FOR_HUMAN.

Inputs: current chat PPT/PDF/slides and optional verbatim transcript, plus class/module materials. If an existing lecture HTML/state exists, CONTINUE it. Do not overwrite existing completed work.

Create inputs/source-manifest.json in the same lecture directory, listing actual source filenames, role (slides/transcript/class/module), and attachment location/provenance. Since this repository is public, do not upload original source-file bytes by default. Preserve filenames and provenance in the input manifest. Copy originals only with appropriate sharing rights, a suitable private destination or explicit authorization, and a verified binary-safe upload; never claim an unverified upload.

Create and incrementally extend a REAL usable HTML5 study page at subjects/<subject>/lectures/<lecture>/study.html with one inline responsive stylesheet (including the PAGE DESIGN classes from 00-shared), ToC, source ledger, build log, stable topic IDs, and data-source-ids. Capture EVERY substantive definition, key term, formula, symbol, example, calculation, figure, table, caveat, comparison, teacher warning/exam tip and student Q&A. Exclude only greetings/filler/off-topic/redundancy. Where transcript exists teacher speech determines coverage, slides fix STT errors and visual references. If Recordings: 0, slides determine coverage and must be covered slide-by-slide without inventing spoken comments.

Source ledger: stable L001... records with slide number/page/timestamp, literal quantitative details, content type, uncertainty and related HTML sections. Preserve course notations exactly; flag apparent source mistakes rather than silently correcting. Note in the ledger which slide charts/diagrams carry exam-relevant information (axes, units, what they show) so later stages can redraw them. Do not claim to have seen slide images if only extracted text was available.

At this stage the HTML holds short, faithful notes per slide group (no long explanations, no external facts, no practice questions); detail lives in the ledger. Build a source coverage checklist from slide 1 to last; validate every covered source line.

Large slidesets: process manageable batches and commit progress. Emit [[STUDY_STEP_MORE:S01]] with verified partial HTML and state next batch; emit [[STUDY_STEP_DONE:S01]] only after complete source coverage and verified GitHub writes. On unable source/file access emit [[STUDY_WAIT_FOR_HUMAN]].

Persist and re-fetch study.html, state.json and inputs/source-manifest.json. If a source input could not be stored as a binary file, record that limitation rather than blocking the reading of an accessible chat attachment. For complete stage set state.stage=1; for partial keep stage=0 and checkpoint next batch. Terminal marker must be the final standalone line.
